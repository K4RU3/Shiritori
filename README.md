# Shiritori (英語版 しりとりボット) v4

Discord で動作する英単語しりとりボット(Rust)。単語の回答はコミュニティ投票(👍/👎)で
承認され、承認された単語はそのルーム(チャンネル)の辞書へ登録されます。

v4 は v3 の Rust リライト版で、以下の改善を含みます:

- 新しいデータ形式: バージョン付き単一 JSON(`shiritori-data` v1、人間可読)
- アトミック保存(tmp→rename)+ 直前状態の `.bak` 退避
- 内蔵 Web 機能: 辞書検索ページ・管理画面・v3 データのインポート移行・JSON エクスポート
- Docker 対応(`/data` ボリュームでデータ永続化、コンテナ再作成後も継続利用)
- 文字数基準のあいまい検索(v3 のバイト/文字混在バグの修正)

## ゲームのルール

- 参加者は自分の順番に、前の単語の末尾から始まる英単語(1語)をチャンネルに送信して回答します
  (例: `apple` → 末尾 `e` から始まる `elephant`)。
- 順番でないユーザーの回答は棄却され、その回答者が進行中の投票があった場合
  「この投票は無効化されました」に切り替わります。
- 既に辞書にある単語(完全一致・大文字小文字は無視)は即時棄却されます。
- 回答は Discord に投票メッセージとして表示され、👍 / 👎 のリアクション(または
  `/vote` コマンド)で過半数に達した時点で決着します:
  - 可決: 単語がルームの辞書に登録され、回答順が1つ進みます
  - 否決: 同じユーザーが再度回答します
- 自分が回答した単語には投票できません。

※ しりとりの「語尾/語頭の自動照合」は実装していません(コミュニティの運用に委ねます)。

## コマンド

### 登録

ボットをメンションすると、そのチャンネルがゲームルームとして登録され、
ギルドにスラッシュコマンドが登録されます。

### メンバーコマンド(通常メッセージ)

| コマンド | 説明 |
|---|---|
| `!queue @user1 @user2 ...` | 回答順を設定します |
| `!addqueue @user` | 回答順の末尾にユーザーを追加します |
| `!addwords word1, word2 ...` | 単語を辞書に直接追加します(管理用途) |
| `!skip [人数]` | 指定した人数の回答をスキップします(省略時 1人) |
| `?単語` | 辞書を検索します(あいまい検索) |

### スラッシュコマンド

| コマンド | 説明 |
|---|---|
| `/vote vote:有効 or 無効` | 最新の回答に票を入れます(過半数で決着) |
| `/find word mode max_dist` | 辞書を検索します(mode: 完全/部分/前方/後方/あいまい) |
| `/skip count` | 回答をスキップします(省略時 1人) |

### 権限

管理コマンド(`!queue` `!addqueue` `!addwords` `!skip`)は、その部屋の
回答順に参加しているユーザー全員が使用できます。回答順が未設定の場合は
誰でも使用できます(初期設定のため)。

## セットアップ(ローカル)

1. Rust 1.85 以上(推奨 stable)を用意します
2. Discord Developer Portal でボットを作成し、以下の Intents を有効化します
   - SERVER MEMBERS INTENT(必要に応じて)
   - MESSAGE CONTENT INTENT(**必須**)
3. `.env` を作成します

```dotenv
DISCORD_BOT_TOKEN=your_token_here

# 任意: Web機能(3つすべて設定した場合のみ有効)
WEB_BIND=0.0.0.0:8080
WEB_PUBLIC_URL=https://dict.example.com
WEB_PASSWORD=admin_password
```

4. 起動します

```bash
cargo run --release
```

## 環境変数

| 変数 | 必須 | 説明 |
|---|---|---|
| `DISCORD_BOT_TOKEN` | ✔ | Discord ボットトークン |
| `DATA_DIR` | | データディレクトリ(`${DATA_DIR}/data.json` に保存。省略時 `./data`) |
| `SHIRITORI_PORT` | | Docker使用時のホスト側ポート(compose が `${SHIRITORI_PORT:-8080}:8080` に展開。省略時 8080) |
| `WEB_BIND` | | Web サーバーの待ち受けアドレス(例: `0.0.0.0:8080`) |
| `WEB_PUBLIC_URL` | | ユーザー遷移用の公開アドレス(辞書検索ページへのリンクに使用) |
| `WEB_PASSWORD` | | 管理画面のパスワード |

Web 機能は `WEB_BIND` / `WEB_PUBLIC_URL` / `WEB_PASSWORD` の **3つすべて** が揃った
場合のみ起動します。いずれかが欠けていればログ 1 行を出して Discord ボットだけが動きます。

## Web 機能

Web を有効にすると、次のページが利用できます。

| パス | 説明 |
|---|---|
| `/` または `/search` | 辞書検索ページ(検索モード・ルーム選択付き) |
| `/healthz` | 死活監視用 |
| `/admin/login` | 管理画面ログイン(パスワード認証) |
| `/admin` | ダッシュボード(ルーム一覧/単語数/進行中投票) |
| `/admin/export` | 現在のデータ(`data.json`)をダウンロード |
| `/admin/upload` | 旧形式(v3)データのインポート |
| `/admin/logout` | ログアウト |

管理画面はログイン成功時に乱数トークンを発行し、HttpOnly クッキーで保持します
(プロセス再起動でセッションは失効します)。

## v3 からの移行

`/admin/upload` から旧形式のデータをアップロードすると、v4 形式へ自動変換して
**マージ** します:

- `rooms.json`(v3 のルーム一覧): キューと進行中投票の復元
  (既存の v4 データが優先されます。キューは既存が空の場合のみ取り込み、
  投票は既存に無い場合のみ復元します)
- `word_{room_id}.idx`(v3 の bincode 辞書): 各ルームの辞書に追加マージ

適用前に現在の状態がバックアップ(`data.json` + `.bak` のローテーション)として
保存されます。`rooms.json` や一部の `.idx` が壊れていても、解析できた範囲だけ
インポートを続行します(結果ページに警告が表示されます)。

v3 と同等の操作をローカルで行う場合や、移行を確認したい場合は
`/admin/export` で `.bak` の状態も残した状態の JSON をダウンロードできます。

## Docker で運用

イメージのビルドと起動:

```bash
docker compose up -d --build
```

`.env` に `DISCORD_BOT_TOKEN`(必須)と任意で Web 用の 3 変数を記載しておいて
ください。ホスト側ポートを変えたい場合は `SHIRITORI_PORT=12345` を `.env`
に追記します(コンテナ内ポートは変わりません)。データは Docker ボリューム
`shiritori-data` の `/data/data.json` に保存され、コンテナを削除・再作成して
も引き継がれます。

ボットは数年単位の連続稼働を想定しています:

- 60 秒ごとに自動保存されます
- `docker compose stop` / `down` で SIGTERM が送られ、保存が完了してから終了します
  (Ctrl+C でも同様に保存後に終了します)
- ゲームを終了させるコマンドはありません。コンテナ再作成後も
  `/admin/upload` によるデータ引継ぎやボリュームの継続利用でそのまま再開できます

### ボリュームに直接触る場合

```bash
docker compose exec shiritori ls /data
docker cp shiritori-v4:/data/data.json ./backup-data.json
```

## 開発

```bash
cargo check               # 静的検査
cargo test                # 90+ のユニット/統合テスト
cargo clippy --all-targets -- -D warnings   # リント(警告 0 を必須化)
cargo fmt                 # フォーマット
```

コードの中核は Discord を介さずテスト可能です:

- `src/words.rs`: 辞書ストアと 5 種の検索モード(完全/前方/後方/部分/あいまい)
- `src/data.rs`: v4 データ形式と永続化(`RoomManager`)
- `src/bot/engine.rs`: 回答フロー・投票・リアクションのロジック(`FakeMessenger` でテスト)
- `src/web/`: axum ベースの Web 機能、v3 旧形式(bincode/serde)のデコード移行
- `src/mean.rs`: 意味(辞書 API)プロバイダの抽象層。現状はプレースホルダで、
  実装して差し替えるだけで Discord に意味を表示させられます
